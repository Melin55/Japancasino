# HPいい感じにしますくん（iikanji）

既存企業サイトのURLから会社・競合を調査し、10件の参考デザインを1〜5点で採点。取得した本文・リンク・パンくずを保持した複数ページのリニューアル案を生成する開発用MVPです。

## 状態

- **実装・サンプル実行済み**：調査結果表示、10件採点、保存・再開、採点の反映、複数ページプレビュー、保持検査、ZIP、修正コメント、削除。
- **実公開ページで確認済み**：公開HTMLの取得（example.com）。
- **実装済み・実API未確認**：OpenAIによる実会社調査、競合成長の根拠確認、10件の実在サイト選定、構成提案。既存キーの利用は承認済みですが、この実行環境にはキーが接続されていません。
- **未公開**：このクラウド環境にはSitesのソース・ビルド・公開ヘルパーがなく、公開URLは発行していません。クラウド側の127.0.0.1は利用者のMacのlocalhostではありません。

この状態を本番完成とは扱いません。サンプルデータは架空の会社・デザインとして画面に明示しています。

## 起動

Node.js 24以上を使用します。

```sh
npm ci
npm start
```

表示されたローカルURL（既定 http://127.0.0.1:3000）を、サーバーと同じマシンのブラウザーで開きます。「まずはサンプルで体験する」はAPIキーなしで動きます。

実際の調査では既存の `OPENAI_API_KEY` をサーバー環境に接続します。既存の管理方法を優先し、必要な場合はGit管理外の `.env.local` を使用できます。キーをブラウザーやチャット、リポジトリへ貼らないでください。変数名は `.env.example` を参照。`OPENAI_MODEL` は既定 `gpt-5.5`、利用権限に合わせて変更できます。

旧来の `python3 -m http.server 8000 --bind 127.0.0.1 --directory public` は静的アセット確認専用です。API操作にはNodeサーバーが必要です。

## 検証

```sh
npm run check
npm test
npm audit --omit=dev
```

テストはネットワーク境界、robots、出典・成長データの検証、好みの信号不足、本文保持と不正HTML、Cookieによる案件分離、同時採点、ZIP書き出し、修正再生成、削除、キー未設定、プロバイダーをテスト用データに置き換えた一連の処理を確認します。OpenAIへ実課金リクエストは送りません。

この作業環境では既存のChromium/Playwrightによるブラウザー検査も実施。確認項目と限界は [検証記録](docs/VALIDATION.md) を参照してください。

## データと運用上の制約

- 案件と採点は `.data/` に保存。認証Cookieを失うと再開できません。画面から案件データを削除できます。バックアップ・チーム認証・保管期限は未実装です。
- これはローカルの単一プロセス用サーバーです。インターネットへ直接公開する前に、認証、共有ストレージ、課金・費用制限、ジョブキュー、監視を追加してください。
- APIキーはサーバーからのみ参照。取得先は公開ドメインに制限し、DNS、IP、転送先、容量、タイムアウトを検査。直接接続時は検査済みIPへ固定します。HTTPプロキシ利用時はプロキシ側でも内部宛先の拒否が必要です。
- 本番参考サイトの画像プレビューはWordPress mShotsへ公開URLを送信します。取得失敗時は元サイトのリンクを表示します。サービス側の可用性・利用条件確認は本番提供前に必要です。
- 取得HTMLを信頼できる命令として扱いません。AI生成コードを実行せず、型を限定した計画からHTMLを描画します。
- フォーム・会員機能・決済・動的ページの機能は移植しません。取得範囲と未確認項目を明示します。ZIPは確認用のnoindex付きです。
