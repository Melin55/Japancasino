# 自律改善ループ

この文書は方法論と導入順であり、定期実行や本番変更を開始したという報告ではない。

## ループの単位

1. 採点、理由、訂正、採否、修正、取得失敗、生成の差分、トークン数を案件単位で記録する。
2. 失敗を「会社の取り違え」「出典の不足」「好みの不一致」「本文欠落」「導線不良」など、再現可能な問題に分ける。
3. 改善候補を1つ変更する。検索クエリ、抽出、参考先の選択、プロンプト、表示部品を同時に変えすぎない。
4. 固定した評価セットで現行版と比較。改善用と評価用は会社・ドメイン単位で分離し、情報漏れを防ぐ。
5. 合格した変更を少数案件で試し、結果を観測。悪化時は以前のバージョンへ戻す。
6. 採用した変更・見送った理由・計測条件を記録し、次のループへ。

## 評価を分ける

| 対象 | 指標 | 判定方法 |
|---|---|---|
| 調査 | 会社同定、主張の根拠、出典の鮮度、競合の妥当性 | 根拠リンクを第三者が確認できる評価セット。AI自己採点は補助 |
| 好み | 未提示候補の評価予測、選び直し、修正回数 | 所有者の採点と後の採否。ランダムな順番も使い位置バイアスを測る |
| 情報保持 | 本文・リンク・パンくず・URLの欠落、未取得範囲 | 取得台帳と生成HTMLの決定的な比較 |
| 操作性 | 10件完了率、再開率、タスク成功、スマホ操作 | 実操作とブラウザー検査。ボタンが見えるだけで合格しない |
| 成果 | 有効問い合わせ、予約、検索・AI流入 | 所有者の好みと分離。母数と比較期間を記録 |
| 費用 | 提案あたりのAPI実額、処理時間、再試行率 | usageと料金表の時点を対応。品質悪化とのトレードオフを確認 |

## 最初の検証

同意を得た少数の企業サイトで、現行案・既存製品・このサービスを同じ入力と条件で比較する。提案者名を隠した比較で「採用したい」「手直しが少ない」を確認する。最初から機械学習の大量データ収集を始めない。

好みは少数の特徴から始める。10件すべて同点なら信号不足。追加の負担が必要なら任意の二者比較を提案する。前半6件・後半4件の適応選択を導入する場合は、固定10件との比較で、操作負担と予測精度が改善することを確認する。ユーザーに出した候補と選定方法のバージョンも保存し、偏りを把握する。

AIOは対象エンジン、質問群、言語、地域、実行日を固定・記録して複数回測る。1回の回答に出た/出なかっただけで改善を断定しない。少ない流入では統計的な勝敗を出さず、利用者テストと定性観察を先に使う。検索サイトのクロール・再評価には時間がかかる。

## 自動化の範囲

低リスクの提案生成・検査・失敗再現は自動化できる。改善候補の自動作成と、本番への自動反映は分ける。価格・法律上の記載・公開URL・フォーム・外部送信に関わる変更は既存の承認範囲を確認する。明示的に承認された範囲だけ反映し、権限を拡張しない。

1試行の費用、最大再生成回数、総処理時間、成功条件、停止条件を先に決める。無限の「生成→自己批評→生成」は行わない。モデル・プロンプト・取得時点・採点・出力・検査結果を同じ案件IDで追跡する。

## 今回実装したものと次の段階

実装済み：ローカルのイベント記録、採点からの暫定的な好み推定、コメントの再生成への引継ぎ、保持検査、usage、呼び出し回数制限、操作テスト。

未実装：複数顧客の集計、計測サービス連携、学習モデルの更新、候補の適応選択、比較実験の自動判定、定期再調査、自動デプロイ。単なる保存を「学習済み」「精度向上」と表示しない。
