# 検証記録

実施日：2026-10-31（日本時間）。実装と実際に確認できた結果を区別する。

## 結果確認済み

- Node.js 24で `npm run check` と `npm test`。11テスト成功。
- 公開サイト `https://example.com/` のHTML取得、ページタイトルと本文抽出。APIキーは使用していない。
- Chromiumでサンプル開始 → 調査結果 → 10件の採点 → 3ページの提案 → 元本文の保持検査 → ページ内ナビゲーションによる移動 → ページ選択 → ZIP取得 → コメント保存 → 再読み込み後の再開。
- 1440px幅のPCと390px幅のスマホを撮影・確認。スマホのトップ画面と採点画面に横スクロールなし。ブラウザーのJavaScriptエラーなし。
- 同時に10件採点しても保存が失われないこと、別Cookieでは案件を読めないこと、クロスオリジン送信の拒否、キーなしで調査済みを装わないことをテスト。
- 料金がdivにある場合、段落の前後に注意書きがある場合の抽出。元の文字列・リンク・アンカー・パンくずを生成HTMLから再検査。
- 異なる採点で配色が変わること、全同点では好みの信号なしと扱うこと、修正コメント「文字を大きく」が再生成で本文18pxへ反映されること。
- 依存ライブラリを修正版に更新。`npm audit --omit=dev`：0 vulnerabilities。
- `npm run evaluate` は実案件のみを集計。現在は実案件がないため `no_live_data` と表示し、品質向上を主張しない。

## ブラウザー検査の再実行

`npm start` を起動した状態で、Playwrightを提供する環境から `node scripts/browser-check.mjs` を実行する。実行環境に応じて `PLAYWRIGHT_MODULE`（モジュールパス）、`CHROMIUM_PATH`（ブラウザー）、`TEST_BASE_URL` を指定できる。今回の環境では既存のPlaywright Coreと `/usr/bin/chromium` を使用。

画像、検査JSON、サンプルZIPはGit管理外の `artifacts/` に出力する。サンプルには架空の企業・デザインを使用。検査の過程で作成したサンプル案件は `.data/` にあり、本番成果の統計には混ぜない。
